4. HALLAZGOS
------------
Hallazgo 1 - Ordenamiento lento en ProductStore.list()
  Como se encontro: benchmark con 10.000 productos, list() tardaba 353 ms
                    (bloquea el servidor un tercio de segundo).
  Causa           : localeCompare("es", {...}) crea un Intl.Collator nuevo en
                    cada comparacion del sort (~130.000 veces con 10k productos).
  Solucion        : crear el Intl.Collator una sola vez y reutilizarlo; los
                    5 filtros encadenados quedaron en un solo recorrido.
  Resultado       : 353 ms -> 8.28 ms (43x mas rapido). Mismo orden de resultados.

Hallazgo 2 - Busqueda por sku lineal (O(n))
  Como se encontro: getBySku, create y update se volvian mas lentos a medida
                    que crecia el almacen (0.7 us con 100 -> 64.7 us con 10.000).
  Causa           : para buscar un sku se recorria todo el almacen.
  Solucion        : indice Map sku -> id que se actualiza en create, update y remove.
  Resultado       : getBySku 365x, create 35x y update 57x mas rapidos; ahora
                    tardan lo mismo con 100 que con 10.000 productos.

Hallazgo 3 - CREATE TABLE en cada peticion (encontrado con la trazabilidad)
  Como se encontro: el header Server-Timing de GET /api/postgres/users mostro
                    que pg.ensureUsersTable se llevaba el 48% del tiempo del servidor.
  Causa           : CREATE TABLE IF NOT EXISTS se ejecutaba en cada GET y POST
                    de /api/postgres/users.
  Solucion        : ejecutarlo una sola vez al primer uso; si falla, se
                    reintenta en la siguiente peticion.
  Resultado       : GET /api/postgres/users  1249 -> 1778 peticiones/s (+42%),
                    p95 12.25 -> 8.78 ms, tiempo de servidor 4.34 -> 1.92 ms.
                    POST /api/postgres/users 1343 -> 1595 peticiones/s (+19%).
                    CPU pico de Postgres 28% -> 9%.

Hallazgo 4 - GET /api/products sin paginacion
  Como se encontro: con 2.060 productos en la base, el endpoint paso de 5.9 ms
                    a 54.6 ms en promedio (182 peticiones/s en vez de ~1.700).
  Causa           : devuelve todos los productos en cada peticion.
  Recomendacion   : paginar con parsePagination (?page=&limit=) como en /users.
